# prontom

通用 Malody `.mc` 轨道映射工具。

当前版本：`2.1.15`

## 用法

```text
prontom.exe input.mc target_columns [lambda] [local_gap_scale] [--ignoreLN|-i] [--globalHoldMapper|-g]
prontom.exe --version
```

`lambda` 省略时默认为 `0`。`lambda` 必须满足 `lambda >= 0`：

- `lambda=0`：严格使用旧的逐 note 映射路径。
- `lambda>0`：使用事件级多对多键型转换；lambda 大于 1 时会进一步稀释降 K 事件。

源轨道数自动读取 `meta.mode_ext.column`。

`local_gap_scale` 省略时默认为 `0`。它直接缩放局部最小间隔：

- `0`：关闭局部约束，行为等价于 v2.1.9。
- `1`：保持当前局部约束。
- `0.5`：局部间隔缩小为原来的 0.5 倍，放宽局部约束。
- 更大的值：按比例增强局部约束。

局部参数直接放在第四个参数位置，例如：

```text
prontom.exe input.mc 10 1 0.5
```

`--ignoreLN` 或 `-i` 会忽略长条的冻结行为：带有 `endbeat` 的 note
仍然保留 `endbeat`，但按普通米参与轨道映射，不再因为长条占用而冻结目标轨道。
例如：

```text
prontom.exe input.mc 10 0.5 0.5 -i
```

`--globalHoldMapper` 或 `-g` 会强制使用含长条谱面的全局 mapper
模式，即使输入是纯米。`-g -i` 同时启用时，长条字段保留但不参与冻结；
删除输出 `endbeat` 后，与删除输入 `endbeat` 再使用 `-g` 的结果一致。

输出文件会写成：

```text
input_to{target_columns}K.mc
```

## 映射规则

- 使用整数矩阵和确定性平衡周期，不使用浮点权重。
- `4→8` 无长条时保持原 `Pro4to8.py` 的逐音符结果。
- 等权目标轨道使用严格的循环平衡序列，例如 `0,1,2,0,1,2...`。
- 长条先按基础映射确定目标轨道，并在 `[beat,endbeat)` 内冻结源轨道和目标轨道。
- 长条冻结后，剩余轨道按 `n-k→m-k` 重新映射。
- 长条发生冲突时，不丢弃后来的长条；前一根长条的 `endbeat` 截短到冲突起点前 `1/4 beat`。
- `lambda=0` 含长条时，第一根长条之前继续使用普通米路径；之后再继承已经消耗的 source phase 和目标轨道状态进入长条冻结路径。
- 如果截短后不再构成正长度长条，则删除前一根的 `endbeat`，保留其起始音符。
- 冻结状态会继承各源轨道已经消耗的周期位置，不会在每次 `n-k→m-k` 重建时重置。
- 普通音符、长条头和长条尾统一遵守 `xmin * m / n` 的最小间隔约束。
- 在全局最小间隔之外，按原谱每个 beat 建立局部下限：遍历该 beat 的各源轨道 note，计算其与同轨道前一个 note 的间隔并取最小值；目标谱该 beat 的同轨道前间隔必须不小于这个局部下限。
- 同一 beat 的目标列会确定性避开已占用列。
- 当矩阵允许列无法满足最小间隔时，确定性去尾后续 note，不跨越到其他源轨道的目标区间。
- 当矩阵允许列全部无法满足最小间隔时，确定性去尾后续 note，并在日志中报告数量。
- 长条分支在所有目标列都不满足最小间隔时也会去尾后续 note，不再保留违规列。
- 事件级路径以同一精确 beat 的键型作为转换事件，并使用原谱 `xmin` 作为间隔约束，不乘 `m/n`。
- 事件级路径使用确定性平衡周期控制增删 note，不使用随机。
- 事件级路径按中心、跨度、间隙和连续性选择目标键型。
- 事件中包含长条和其他同起点 note 时，新增键是否继承长条由同一套平衡扩展算法决定；继承长条的新增键统一使用代表性 `endbeat`。
- 单独一根长条事件的新增键保持短 note，不会因为扩展键数而无条件增加长条。
- 纯长条事件的重复源键型使用确定性候选轮换，避免长条长期固定在同一组目标轨道；普通事件和混合事件仍使用原本的最低形状代价选择。
- `2.1.7` 的全局左右朝向规范化已撤回；本版本恢复 `2.1.6` 的形状候选和映射路径，避免改变已经稳定的形状相似性。

## 构建

使用 MinGW-w64：

```text
g++ -std=c++17 -O2 -municode -s -o prontom.exe prontom.cpp
```

`json.hpp` 是单头文件依赖，已随仓库保存。
